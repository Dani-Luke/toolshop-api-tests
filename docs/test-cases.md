# Тест-кейсы Toolshop API

## TC-01. Успешная регистрация пользователя

| Поле | Значение |
|---|---|
| ID | TC-01 |
| Название | Успешная регистрация пользователя с уникальным email |
| Приоритет | High |
| Тип | Позитивный |
| Предусловие | Postman открыт; выбран environment `Toolshop Dev`; API доступен |
| Тестовые данные | `first_name`: Ivan  
`last_name`: Ivanov  
`password`: QaToolshop_2026_Ivan!  
`email`: уникальный email, формируемый через `{{$randomUUID}}` |

### Шаги

1. Открыть коллекцию `Toolshop API Tests`.
2. Открыть запрос `POST register user`.
3. Убедиться, что выбран environment `Toolshop Dev`.
4. Открыть вкладку **Scripts → Pre-request**.
5. Убедиться, что email сохраняется в переменную `registered_email` и формируется с использованием `{{$randomUUID}}`.
6. Открыть вкладку **Body → raw → JSON**.
7. Убедиться, что в Body указаны `first_name`, `last_name`, `password` и `{{registered_email}}`.
8. Нажать **Send**.
9. Проверить статус-код ответа.
10. Проверить, что в ответе возвращается email пользователя.
11. Проверить, что email из ответа совпадает со значением переменной `registered_email`.
12. Проверить, что в ответе есть идентификатор созданного пользователя.

### Ожидаемый результат

- Статус-код: `201 Created`.
- В ответе содержатся данные созданного пользователя.
- `email` в ответе совпадает с отправленным.
- Пользователь создаётся в системе.

### Постусловие

Пользователь создан и может быть использован для авторизации.

## TC-02. Успешная авторизация пользователя

| Поле | Значение |
|---|---|
| ID | TC-02 |
| Название | Успешный логин зарегистрированного пользователя |
| Приоритет | High |
| Тип | Позитивный |
| Предусловие | Пользователь зарегистрирован; environment `Toolshop Dev` выбран |
| Тестовые данные | `email`: email зарегистрированного пользователя  
`password`: валидный пароль пользователя |

### Шаги

1. Открыть запрос `POST login user`.
2. Убедиться, что выбран environment `Toolshop Dev`.
3. Открыть вкладку **Body → raw → JSON**.
4. Убедиться, что указаны валидные `email` и `password`.
5. Нажать **Send**.
6. Проверить статус-код ответа.
7. Проверить, что в ответе возвращается `access_token`.
8. Проверить, что `access_token` сохранён в environment.
9. Проверить, что `user_id` сохранён в environment.

### Ожидаемый результат

- Статус-код: `200 OK`.
- В ответе возвращается `access_token`.
- `access_token` сохраняется в environment.
- `user_id` сохраняется в environment.

### Постусловие

Пользователь авторизован; его токен доступен для последующих запросов.

## TC-03. Создание корзины авторизованным пользователем

| Поле | Значение |
|---|---|
| ID | TC-03 |
| Название | Успешное создание корзины авторизованным пользователем |
| Приоритет | High |
| Тип | Позитивный |
| Предусловие | Пользователь зарегистрирован и авторизован; `access_token` сохранён в environment |
| Тестовые данные | `Authorization`: `Bearer {{access_token}}` |

### Шаги

1. Открыть запрос `POST create cart`.
2. Убедиться, что выбран environment `Toolshop Dev`.
3. Открыть вкладку **Authorization**.
4. Убедиться, что выбран тип `Bearer Token`.
5. Убедиться, что в поле Token указан `{{access_token}}`.
6. Нажать **Send**.
7. Проверить статус-код ответа.
8. Проверить, что в ответе возвращается идентификатор корзины.
9. Проверить, что `cart_id` сохранён в environment.

### Ожидаемый результат

- Статус-код: `201 Created`.
- В ответе возвращается `cart_id`.
- `cart_id` сохраняется в environment.

### Постусловие

Создана новая корзина, доступная по сохранённому `cart_id`.

## TC-04. Получение списка товаров

| Поле | Значение |
|---|---|
| ID | TC-04 |
| Название | Успешное получение списка товаров |
| Приоритет | High |
| Тип | Позитивный |
| Предусловие | API доступен; environment `Toolshop Dev` выбран |
| Тестовые данные | Отсутствуют |

### Шаги

1. Открыть запрос `GET products`.
2. Убедиться, что выбран environment `Toolshop Dev`.
3. Нажать **Send**.
4. Проверить статус-код ответа.
5. Проверить, что в ответе содержится массив товаров.
6. Проверить, что у товаров есть идентификатор `id`.
7. Проверить, что `product_id` первого товара сохранён в environment.

### Ожидаемый результат

- Статус-код: `200 OK`.
- В ответе возвращается список товаров.
- У каждого товара есть уникальный `id`.
- `product_id` сохраняется в environment.

### Постусловие

`product_id` доступен для использования в запросе добавления товара в корзину.

## TC-05. Добавление товара в корзину

| Поле | Значение |
|---|---|
| ID | TC-05 |
| Название | Успешное добавление валидного товара в корзину |
| Приоритет | High |
| Тип | Позитивный |
| Предусловие | Пользователь авторизован; корзина создана; `product_id` получен из списка товаров |
| Тестовые данные | `cart_id`: из environment  
`product_id`: из environment  
`quantity`: 1  
`Authorization`: `Bearer {{access_token}}` |

### Шаги

1. Открыть запрос `POST add item to cart`.
2. Убедиться, что выбран environment `Toolshop Dev`.
3. Убедиться, что в URL используется `{{cart_id}}`.
4. Открыть вкладку **Authorization**.
5. Убедиться, что выбран Bearer Token и указан `{{access_token}}`.
6. Открыть вкладку **Body → raw → JSON**.
7. Убедиться, что передаются `product_id` и `quantity: 1`.
8. Нажать **Send**.
9. Проверить статус-код ответа.
10. Открыть запрос `GET cart by id`.
11. Нажать **Send**.
12. Проверить, что добавленный товар отображается в `cart_items`.
13. Проверить, что `quantity` товара равен `1`.

### Ожидаемый результат

- Запрос добавления возвращает успешный статус.
- Товар с переданным `product_id` появляется в `cart_items`.
- Количество товара соответствует `1`.

### Постусловие

В корзине есть один добавленный товар.

## TC-07. Удаление товара из корзины

| Поле | Значение |
|---|---|
| ID | TC-07 |
| Название | Успешное удаление добавленного товара из корзины |
| Приоритет | High |
| Тип | Позитивный |
| Предусловие | Пользователь авторизован; корзина создана; товар добавлен в корзину |
| Тестовые данные | `cart_id`: из environment  
`product_id`: из environment  
`Authorization`: `Bearer {{access_token}}` |

### Шаги

1. Открыть запрос `DELETE remove product from cart`.
2. Убедиться, что выбран environment `Toolshop Dev`.
3. Убедиться, что в URL используются `{{cart_id}}` и `{{product_id}}`.
4. Убедиться, что в Authorization указан `{{access_token}}`.
5. Нажать **Send**.
6. Проверить статус-код ответа.
7. Открыть запрос `GET cart by id — after delete`.
8. Убедиться, что в URL используется `{{cart_id}}`.
9. Убедиться, что в Authorization указан `{{access_token}}`.
10. Нажать **Send**.
11. Проверить статус-код повторного запроса корзины.
12. Проверить, что удалённого товара нет в `cart_items`.
13. Проверить, что массив `cart_items` пустой.

### Ожидаемый результат

- Статус-код запроса удаления: `204 No Content`.
- Товар удаляется из корзины.
- Повторный запрос корзины возвращает `200 OK`.
- Массив `cart_items` пустой.

### Постусловие

Товар удалён из корзины; корзина остаётся созданной, но не содержит товаров.
